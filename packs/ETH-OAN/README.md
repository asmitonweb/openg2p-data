# ETH-OAN — Ethiopia, current hierarchy down to kebele

| | `ETH` | `ETH-OAN` |
|---|---|---|
| Levels | country → region → zone → woreda | country → region → zone → woreda → **kebele** |
| Units | 1 / 15 / 107 / 1,148 | 1 / 14 / 125 / 1,362 / 19,535 |
| Hierarchy as of | OCHA COD-AB cut | after the 2021–2023 reorganisation (Sidama, South West, Liyu zones) |
| Boundaries | yes | `ETH`'s, for the unchanged units (none for kebeles or the new units) |
| Kebele | address text (`address.json`) | a level |
| Samples | on woredas, kebele as address text | the same people, on their kebele unit |

Generated by [`../../scripts/packs/build_eth_oan_pack.py`](../../scripts/packs/build_eth_oan_pack.py)
from the OpenAgriNet farmer registry's location catalog. Code lists, domains and
`address.json` are copied from `ETH`, so both packs describe a farmer the same way. Do not
edit the files here by hand; re-run the script:

```bash
cd scripts/packs
python3 build_eth_oan_pack.py --source <geo_level_values.json> --base ../../packs/ETH --out ../../packs/ETH-OAN
python3 validate_pack.py ../../packs/ETH-OAN
```

`manifest.json` records the source file's SHA-256, so you can tell whether a rebuild used the
same input.

## Selecting it

Set `geoSeed.countryPack: ETH-OAN` in the `openg2p-master-data` chart. Every region, zone and
woreda whose unit COD-AB also has keeps COD-AB's P-code (`pcode_source: OCHA COD-AB`).

## Boundaries

`boundaries/` carries `ETH`'s polygons for the units that are still the same unit, so Master
Data seeds them with the hierarchy and serves them (`/catalogue/get_geo_boundary`) to every OAN
registry and dashboard: one map, the same ids as the location fields. A woreda keeps its
polygon when its code is COD-AB's; a region or zone when, besides that, none of `ETH`'s woredas
inside it has left it, so no polygon is larger than its unit now is. Kebeles and the units
created since 2021 have none. `manifest.json` records the count per level
(`boundary_coverage`); today 1 country, 7 of 14 regions, 85 of 125 zones and 1,063 of 1,362
woredas. A registry's map pin finds the woreda under it and takes the region and zone from its
code, which nest; where there is no polygon, the location is chosen from the lists.

The polygons are OCHA COD-AB (CC BY-IGO): show the attribution wherever they are drawn.

## Identifiers and migrating existing records

Ids follow the pack contract: the id is the P-code, and each child adds two digits to its
parent's code. Compared with the source catalog:

- Prefixes are dropped (`woreda-ET010101` → `ET010101`).
- 56 woredas whose code did not extend their zone's code get a new code under their zone. The
  new code is never one that `ETH` uses for a different unit.
- All kebeles are re-numbered `<woreda code><01–99>`.
- 17 childless duplicates of a re-parented woreda are merged into the woreda that has the
  kebeles.
- Where distinct units share a name under one parent, every unit is kept. The second and later
  ones carry their id in `level_value_mnemonic`; `display_name` is unchanged.

[`migration/id_map.csv`](migration/id_map.csv) lists every source id with its pack id and
whether it was kept, re-minted or merged. Use it to rewrite geo ids already stored in a
registry before you point that environment at this pack.

## `SELF` in Relationship to the head

`ETH`'s list no longer has `SELF`, so on its own it fails `validate_pack.py`: no value carries
the `head_of_household` role, and six samples use `SELF`. The pack contract needs one value with
that role, so this pack adds `SELF` (sort order 1, role `head_of_household`) from
[`eth_oan_additions/values/`](../../scripts/packs/eth_oan_additions/values). The farmer registry
marks the head with Is Head, and accepts `SELF` only for that member. If `ETH` gets `SELF` back,
the build stops and names the addition to drop.

## Lists the farmer registry adds

The farmer registry's own choice lists come from Master Data like every other dropdown, so the
lists `ETH` does not have are added from
[`eth_oan_additions/`](../../scripts/packs/eth_oan_additions) and never replace a base list:
`LANGUAGE`, `LIVESTOCK_BODY_CONDITION`, `LIVESTOCK_PRODUCTION_TYPE`, and the document and
finance lists `IDENTITY_DOCUMENT_TYPE`, `BANK_DOCUMENT_TYPE`, `LAND_DOCUMENT_TYPE`,
`REPRESENTATIVE_DOCUMENT_TYPE`, `FARMER_DOCUMENT_TYPE`, `DOCUMENT_PURPOSE`,
`PHONE_NUMBER_TYPE`, `FINANCE_ACCESS_TYPE`. Their codes are the values the registry already
stores (`FAYDA`, `PRIMARY`, `LOAN`, ...), so an existing record needs no rewrite.
